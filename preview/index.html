How Concurrency-Safe Booking Works

PostgreSQL row-level locking guarantees zero double-bookings, even under extreme concurrent load.

1

User clicks "Book Seats"

Frontend sends POST /api/v1/bookings with seat IDs and idempotency key.

2

Rate Limiting (Redis)

Redis checks the user hasn't exceeded 10 booking attempts per minute.

redis.incr("rate:booking:{userId}") → limit: 10/min
3

Idempotency Check (Redis)

If the same idempotency key was already processed, return the cached result. Prevents duplicate bookings from network retries.

redis.get("idempotency:{key}") → cached? return result
4

PostgreSQL Transaction Begins

A new database transaction starts. This is where the magic happens.

BEGIN;
5

🔒 SELECT ... FOR UPDATE (Row Lock)

PostgreSQL locks the requested seat rows. Other transactions trying to lock the same rows must wait.

SELECT * FROM seats WHERE id = ANY('{A03,A04}') ORDER BY id ASC   -- deterministic lock order FOR UPDATE;       -- OTHER TRANSACTIONS WAIT HERE
6

Check Availability

While holding the lock, verify ALL requested seats are AVAILABLE. If any are booked, rollback — no partial booking.

IF any seat.status != 'AVAILABLE' → ROLLBACK;
-- No partial bookings. All or nothing.
7

Create Booking & Update Seats

Insert booking record, mark seats as BOOKED, all within the same transaction.

8

COMMIT

Transaction commits. Locks release. The winning transaction persists. Losers get a 409 Conflict.

COMMIT; -- ✅ Seat booked. Locks released.
-- Other waiting transactions wake up
-- and find the seat is now BOOKED.
9

Background Jobs & WebSocket Broadcast

After commit: queue confirmation email via BullMQ, broadcast seat change via Socket.io to all connected clients.

emailQueue.add("booking-confirmation", data);
broadcastBulkSeatUpdate(eventId, seatUpdates);
// All clients see the seat change instantly

Why no double bookings?

User 1 ──────────────────┐
User 2 ──────────────────┤
User 3 ──────────────────┤
User 4 ──────────────────┤
User 5 ──────────────────┤
                         ↓
                    Booking API
                         ↓
               PostgreSQL Transaction
                         ↓
              SELECT ... FOR UPDATE
                         ↓
               Seat A03 Row Lock Acquired
                         ↓
           ┌────────────┴────────────┐
           ↓                         ↓
     User 1                User 2,3,4,5
     SUCCESS               WAIT... (locked)
     COMMIT                ↓
                          Lock released
                          ↓
                     Seat is BOOKED
                          ↓
                    409 CONFLICT
                    (× 4 users)

Result: 1 booking, 0 double-bookings
